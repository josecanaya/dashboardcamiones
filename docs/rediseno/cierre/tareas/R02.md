2. Leer dos archivos por día; recorrer días con máximo cuatro días simultáneos. Ordenar respuesta por día ascendente. No devolver rutas/baseUrl/records/mensaje crudo de filesystem.
3. Añadir POST /api/truckflow/source-availability; validar fechas con daysInclusive; 400 para rango inválido. Pasar DATA_ROOT y lista de días al módulo. 500 JSON genérico si falla infraestructura no clasificable por archivo.
4. Cliente `postSourceAvailability({startDate,endDate})` usa prefijo y parseJson existentes; devuelve `{days: SourceDay[]}` sin cargar eventos.
5. Tests con directorio temporal: ausente, corrupto, payload error con records=[], diario global válido vacío/no vacío, sitio específico, ventana parcial, ventana completa sin siteFilter, legacy array sin metadatos. Verificar estado/count/fetchedAt y ausencia de secretos en respuesta.
