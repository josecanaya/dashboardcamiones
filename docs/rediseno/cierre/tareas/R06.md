## Hacer
1. DataWorkspace ensambla los cuatro bloques del documento principal. No crear estado local de fechas/operación: consumir dataPreparation del provider. Una sola pareja Desde/Hasta con labels.
2. PeriodEditor: Semana anterior y Últimos 7 días completos usando calendario de Buenos Aires, setter atómico de ambas fechas. Rango inválido deshabilita Revisar disponibilidad, muestra causa específica; no autoenviar POST.
3. SourceCoverageCards: Cámaras/Excel/Procesamiento. Chips/textos del contrato; detalle diario colapsado con columnas Día/Eventos/Alertas/Excel/Estado. Mostrar null como sin dato. Datos numéricos solo de respuesta real.
4. PreparationProgress: etapa actual, pasos completados/total, lista desplegable de pasos y errores; indeterminado dentro del request; botón Detener después del paso actual. role=status para progreso, alert para error, sin anuncios por cada fila.
5. Una CTA principal elegida según contrato; no mostrar simultáneamente Cargar/Componer/Procesar todo. En ready mostrar enlaces Ver tiempos, Ver resumen ejecutivo y Ver anomalías.
6. HistoricalWorkspace mantiene h1 por ruta pero fuera de Datos reemplaza editor/formulario por rango activo+estado+limitaciones+Link a `/estadisticas/datos`. En Datos deja que DataWorkspace renderice el único editor. Añadir título `datos: ['Datos', 'Prepará un período para todos los indicadores y reportes.']`.
7. Estado sin conexión muestra error recuperable y último active; no desaparece contenido preparado. Elementos de input no se deshabilitan por un simple render, solo por operación incompatible.

## No hacer
- No otra librería, no contexto nuevo, no formularios repetidos por pantalla.
- No eliminar filtros de circuito, día o franja que filtran resultados dentro del período.

`npm test -- --maxWorkers=2`, `npm run check:arch`. UI a 1440×950 y 1024×768: rango/estado/CTA visibles antes de abrir detalles, sin overflow horizontal de página. Teclado permite recorrer y activar todos los controles. Capturas de idle, disponible, fuentes pendientes, preparando y error con mock de test (identificar como simulación, nunca como datos reales).
